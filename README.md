# MEXBET — локальная виртуальная спортивная платформа

MEXBET — локальная спортивная платформа с API-Sports линией, виртуальным балансом и премиальным интерфейсом.

> **Важно: это учебный демо-проект.** Здесь используются только виртуальные деньги и придуманные спортивные события. Нет реальных платежей, вывода средств, интеграций с букмекерами или сбора данных с сайтов.

## Запуск

Требуется Node.js 18+.

```bash
npm install
npm run dev
```

Откройте адрес, который покажет Vite (обычно `http://localhost:5173`).

Для production-проверки:

```bash
npm run build
npm run preview
```

## Возможности демо

- каталог футбольных и хоккейных событий API-Sports с поиском и фильтрами;
- купон с одиночными ставками, коэффициентами и расчётом возможного выигрыша;
- локальное списание виртуального баланса и история операций;
- личный кабинет со сводными показателями;
- админ-панель для корректировки баланса с обязательной причиной и журналом аудита;
- данные сохраняются только в `localStorage` текущего браузера.

Проект работает без API-ключа на резервной линии. Для получения реальных футбольных и хоккейных событий через API-Sports:

1. Создайте аккаунт на [API-Sports](https://api-sports.io/).
2. Скопируйте `.env.example` в `.env.local`.
3. Добавьте ключ в `VITE_API_SPORTS_KEY`.
4. Запустите `npm run dev`.

Для GitHub Pages добавьте ключ в репозитории через **Settings → Secrets and variables → Actions → New repository secret** с именем `API_SPORTS_KEY`, затем запустите workflow заново. Без этого секрета GitHub Pages физически не может подключить API: браузер получает пустой `VITE_API_SPORTS_KEY`.

Важно: ключ `VITE_*` попадает в браузерный bundle. Для настоящего production-сайта используйте серверный proxy/serverless endpoint и храните ключ только на сервере. API-Sports не является универсальным источником киберспорта, поэтому киберспортивная лента в этом демо остаётся отдельной mock-линией.

События открываются настоящей ссылкой с `target="_blank"` в отдельной вкладке. API запрашивает события на сегодня и следующие 6 дней, включая хоккей, и отбрасывает завершённые/отменённые матчи.

Пользовательское пополнение в профиле добавляет только виртуальные средства и записывается в историю. Админ-раздел убран из публичной навигации и открывается владельцем через `?admin=1`; это не настоящая приватность на GitHub Pages. Для действительно закрытой админки нужен backend с авторизацией, ролями и базой данных.

Ставки и пополнения в текущей версии виртуальные: GitHub Pages не может безопасно принимать платежи или хранить платёжные секреты. Реальное пополнение требует отдельного backend, авторизации пользователей, базы данных и подключённого платёжного провайдера; не добавляйте платёжные ключи во frontend или GitHub Pages bundle.

## Публикация обычной ссылкой через GitHub Pages

Сайт можно открыть без локального сервера и сторонних хостингов:

1. Создайте новый публичный репозиторий на GitHub.
2. Загрузите в него все файлы этого проекта (включая `.github/workflows/deploy-pages.yml`).
3. Откройте вкладку **Actions** и дождитесь завершения `Deploy to GitHub Pages`.
4. В репозитории откройте **Settings → Pages** и выберите **Source: GitHub Actions**, если GitHub попросит это сделать.
5. После успешного workflow ссылка появится в **Settings → Pages**. Обычно она выглядит так:
   `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`

При каждом следующем обновлении ветки `master` GitHub автоматически пересоберёт и опубликует сайт. База данных и сервер для этого демо не нужны: состояние каждого посетителя хранится только в его браузере.
